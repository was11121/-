# Remedy（现实补丁 Agent）— 项目简介

## 一、项目解决的问题

市面上大多数 AI 助手是「一次性问答工具」：每次对话都从零开始，不记得用户是谁、习惯什么、正在做什么事；用户提出的目标和计划说完就忘，缺乏「说了要做的事，是否真的落地」的闭环；不同产品各管一段——聊天工具管对话、笔记工具管文档、待办工具管任务，用户自己要在三者之间来回搬运信息。

Remedy 要解决的核心问题是：**让 AI 助手从"回答问题"升级为"持续了解你、并帮你把想法落地"的个人智能体**。它通过跨会话的记忆积累、基于大五人格的行为画像、以及"现实补丁"状态机（草稿 → 确认应用 → 可回滚），把"用户说的话"转化为"可追踪、可验证、可撤销的现实变化"，而不是聊完就忘的对话记录。

## 二、目标用户与使用场景

**目标用户：**
- 需要长期陪伴式助手的个人用户（学习者、自由职业者、知识工作者）；
- 需要跟踪多项目/多任务进展、又不想被复杂项目管理工具拖慢的轻量用户；
- 希望 AI 能"懂自己"而不是每次都要重新交代背景的用户。

**典型使用场景：**
1. **长期目标追踪**：用户说"我在准备考研，每天要背 50 个单词"，Remedy 记住这个目标，后续对话中主动跟进进度、给出督促或鼓励，而不需要用户每次重新说明背景。
2. **项目秘书 / 现实补丁**：用户在对话中同步一项工作进展（如"接口联调完成了"），Remedy 生成一条待确认的"现实补丁"草稿，用户确认后正式落库到项目看板，出错可一键回滚，避免 AI 擅自"帮用户做决定"。
3. **私有知识库问答**：用户上传自己的文档（PDF/Word/PPT/Excel），Remedy 清洗、索引后可基于权威文档做有引用的问答，避免模型瞎编。
4. **人格自适应督促**：Remedy 从对话中估计用户的大五人格（开放性/尽责性/外向性/宜人性/神经质），据此调整督促策略——对容易拖延者给出更具体的分步提示，对高神经质用户给出更多情绪缓冲。
5. **多渠道统一入口**：同一套记忆与画像可同时服务 Web 控制台和 QQ（OneBot），用户换渠道对话，Remedy 依然认得他。

## 三、核心功能

| 模块 | 功能 |
|---|---|
| **统一交互协议** | `unified_agent/` 提供跨渠道（Web/QQ）统一的请求-响应协议，接同一套记忆与画像 |
| **反馈记忆** | 自动从对话中提取偏好/身份/指令类记忆，带置信度与出现次数，支持编辑、遗忘、按证据链级联清理 |
| **3D 记忆图谱**（本次新增） | 基于"同证据来源"和"同类目"关系，将用户记忆实时渲染为可交互的 3D 关系图，直观展示记忆之间的关联结构 |
| **大五人格画像** | 从对话中估计五大人格维度，映射为"该督促什么 / 该发挥什么长处"的具体建议，非诊断、非角色扮演 |
| **AI 图书馆** | 文档上传、清洗、SHA-256 去重、检索，回答带引用来源，支持 PDF/Word/PPT/Excel |
| **项目秘书 / 现实补丁** | 工作区看板、任务同步、"草稿 → 确认应用 → 回滚"三态状态机，杜绝 AI 擅自变更现实状态 |
| **联网检索** | searxng / Tavily / Jina Reader 多通道自动故障转移，可选 SSH 中转应对网络受限场景 |
| **主动思维 Tip** | 启发式引擎检测重复循环交互和未确认风险，主动提示换角度思考 |
| **身份认证与数据隔离** | 注册/登录、Bearer Token、admin/user 双角色，普通用户仅可访问自身数据，管理员操作全程审计留痕 |
| **多渠道适配** | Web 控制台 + QQ (OneBot) 双入口，统一底层能力 |

## 四、技术方案

- **后端**：Python + Flask，REST API（详见仓库 `API.md`），SQLAlchemy 统一数据访问层
- **数据存储**：默认 SQLite（单文件即可整库备份），生产环境通过 `DATABASE_URL` 一键切换 PostgreSQL，业务代码无需改动
- **前端**：原生 HTML/CSS/JS 控制台（`static/redesign/`），3D 记忆图谱基于 three.js + 3d-force-graph 渲染
- **模型接入**：默认对接 DeepSeek 官方 API，未配置密钥或网络异常时自动降级为本地规则响应器，保证核心功能（记忆/图书馆/秘书/Tip）离线也可完整验证
- **人格识别**：优先使用 Hugging Face `Minej/bert-base-personality`（transformers + torch），未安装模型依赖时自动回退中文启发式规则，可用环境变量强制跳过模型下载
- **认知引擎**：Python 实现为默认路径，预留 C++ 动态库适配器接口（`cognitive_engine/`），加载失败自动回退 Python，不影响可用性
- **联网检索**：searxng（可 Docker 一键起）/ Tavily / Jina Reader 三通道自动故障转移，可选 SSH 中转
- **部署**：自带 `Dockerfile` + `docker-compose.yml`，一条命令 `docker compose up -d --build` 即可在 Linux 服务器起服务 + PostgreSQL，`/health` 健康检查 + 自动重启

## 五、创新点

1. **"现实补丁"状态机**：区分于普通聊天记录，用户的项目进展变更必须经过 Draft → Applied → Rolled Back 的显式确认流程，AI 不会"自作主张"改变用户的现实状态，同时保留完整审计与回滚能力。
2. **人格驱动的行为策略，而非人格驱动的说话风格**：大五人格识别结果不用来让 AI"扮演"某种性格，而是用来决定"今天该督促什么、该发挥什么长处"，是行为建议引擎而非角色扮演。
3. **全链路可离线验证**：无论是 LLM、人格模型还是联网检索，任一外部依赖不可用时都有本地兜底路径，核心记忆/图书馆/秘书闭环始终可演示、可测试，不依赖外部密钥。
4. **3D 记忆关系图谱**：把原本只能列表展示的碎片化记忆，按证据链和类目关系合成图结构并做 3D 可视化，让用户直观看到"AI 记住的关于我的东西"是如何关联起来的。
5. **单库多角色的数据隔离**：所有用户数据集中在一个数据库中按 `user_id` 分区，而非每人一个文件，兼顾了"备份简单"（单文件/单库即可全量备份）与"访问隔离"（越权访问严格返回 401/403，全程审计）。

## 七、使用方式 / 演示入口

**本地一键运行：**
1. 双击项目根目录 `start.bat`（Windows），自动检测环境并在浏览器打开控制台 `http://127.0.0.1:8091/`
2. 或命令行运行：
   ```powershell
   pip install -r requirements.txt
   python app.py
   ```
3. 未配置 `MODEL_API_KEY` 时自动使用本地规则响应器，记忆、图书馆、秘书、Tip 全部功能仍可完整验证。

**Docker 生产部署：**
```bash
cp .env.example .env   # 填写密钥
docker compose up -d --build
```

**演示路径：** 打开控制台 → 注册账号 → 对话页发送几句包含个人偏好/身份/目标的话 → 切换到「记忆与画像」「记忆图谱」查看记忆自动沉淀与可视化 → 切换到「项目秘书」体验现实补丁的确认/回滚流程 → 上传文档体验 AI 图书馆检索问答。
